## 一、现状结论：本项目已是上游超集

### 1.1 上游仓库对比

上游开源仓库 `cxw521/qq-farm-automation-bot` 最后一次提交为 **26.3.29**（commit `bf30e57`），该提交**恰好存在于本项目历史中**（本项目 fork 自上游并持续升级）。

| 维度 | 上游仓库 | 本项目（当前） |
|---|---|---|
| 后端服务 | 22 个 | **33 个**（+11 个基础设施服务） |
| 前端页面 | 7 个 | **8 个**（+ Scheduler 调度页） |
| 版本体系 | 无（Update.log 手工记录） | 语义化版本 + Git 标签 + 4 处版本号一致 |
| 高级功能 | 无 | **12 项**（审计/诊断/重试/告警/Doctor 等） |

**上游独有但本项目已包含的功能**：QQ 扫码登录、好友巡查、偷菜、批量导入 GID、自定义防偷秒数、化肥自动购买、1×1 活动种子种植、Docker 部署、卡密系统等 —— **全部已在本项目中**。

**结论**：本项目功能上已经完全覆盖上游，"把开源仓库功能全部整合"实际已完成。真正的升级方向是**产品化与运营化**（见下文）。

### 2.1 版本号现状

| 文件 | 当前值 | 状态 |
|---|---|---|

| `CHANGELOG.md` | 停在 v2.3.2 | ❌ **落后 1 个版本** |
| Git 标签 | 无 v2.4.0 | ❌ **无标签可回退** |

### 2.2 版本管理升级方案

1. **补发 v2.4.0 Git 标签**：`git tag v2.4.0 <当前提交>`，让回退点立即可用。
2. **补齐 CHANGELOG v2.4.0 记录**（Added/Changed/Fixed/Security）。
3. **发布流程标准化**：今后每次发布执行 `scripts/release.js`（新增），自动完成：
   - 校验 4 处版本号一致（version.json + 3 个 package.json）
   - 更新 `version.json` 的 build 时间戳
   - 生成/校验 CHANGELOG 条目
   - 打 Git 标签 `vX.Y.Z`
   - 输出发布摘要
4. **回退机制**：每版发布后可通过 `git checkout vX.Y.Z` 一键回退；`runtime-doctor` 已能读取版本清单用于前端展示当前版本。

## 五、风险与约束

- **兼容性**：全部新增向后兼容，不破坏现有 API/数据格式；JSON 存储格式不变。
- **测试**：每批完成运行 `pnpm test`（现有 109 测试）+ lint + build，新增功能配套单测/E2E。
- **隐私**：告警/推送配置中 token 类字段沿用脱敏规则（审计、诊断包已实现）。
- **性能**：不引入重型依赖（图表用轻量方案如 ECharts 按需引入或自绘 SVG）。
