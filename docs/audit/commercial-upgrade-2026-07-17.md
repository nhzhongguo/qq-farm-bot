## 产品定位与评分

本项目是**本地优先的 QQ 农场多账号自动化控制台**，而不是面向公网、百万用户的 SaaS 平台。它已形成账号隔离、Worker 自动化、策略配置、实时日志和基础后台的闭环。

当前评分：**72 / 100**。

优势：

- Node.js + Express/Socket.IO + Vue 3/Pinia 的分层清晰；每账号独立 Worker，并有请求队列和调度器。
- 农场、好友、仓库、奖励、策略、账号、卡密与基础管理员功能覆盖完整。
- 原子 JSON 写入与备份恢复、密码 PBKDF2、登录限流、HTTP 安全头和账号访问隔离已存在。
- Vue 面板已有主题、响应式布局、实时状态与日志过滤。

主要风险：

- 微信扫码仍依赖外部协议引擎；当前项目不能自行生成可用微信二维码。
- 默认管理员首次登录此前可获得完整接口权限；本轮已在服务端强制拦截。
- 内存会话没有绝对/空闲过期；账号 Code 和 JSON 数据尚无静态加密与密钥轮换。
- JSON 文件适合单机，不具备多实例事务与并发写保护。
- 运行日志和账号日志未形成持久化审计、错误诊断包与指标体系。

## 架构盘点

| 领域 | 当前实现 | 结论 |
| --- | --- | --- |

| 测试交付 | Node Test、Playwright 冒烟、Docker Compose、跨平台 pkg | 后端安全回归较好；前端关键业务、移动端、断网和权限测试不足，且无 CI。 |

## 功能完成度

### 已完整实现

- QQ 扫码与手动 Code 添加、多账号新增/编辑/启停/删除、用户账号隔离。
- 农场巡查、收获、种植、浇水、除草、除虫、施肥、土地升级、背包使用/出售、日常奖励。
- 好友同步、偷菜、帮助、批量操作、互动记录、好友/作物黑名单和静默时段。
- 作物分析与种植策略、下线提醒、Webhook/推送渠道。
- 管理员/普通用户、卡密、公告、系统配置、登录日志、基础安全防护。
- 实时状态、运行日志、账号日志，及本轮新增的调度中心。

### 半成品

- 微信扫码：同源后端会话代理、限流、超时、脱敏已具备，但没有可信协议服务的部署/健康检查/供应商验收。
- 多用户：角色和账户隔离存在，但仅 `admin/user` 两级，缺精细权限、会话管理和操作审计。
- 调度可观测性：快照和本轮 UI 已具备，缺持久化执行历史、告警和任务级重试策略。
- 备份恢复：主/备份恢复存在，缺校验、加密、版本、演练与异机备份。

### 缺失项

- 健康检查详情、运行环境 doctor、失败诊断包、日志导出与告警规则。
- 管理操作审计、配置模板与导入导出、批量账号运维。
- 会话 TTL/MFA/设备会话、敏感字段加密、密钥轮换。
- 404 页面、无障碍基线、全局搜索/快捷键、前端错误与性能监控。
- CI、API 文档、集成与关键路径 E2E 覆盖。

## 本轮已实施

1. **调度中心**：新增 `web/src/views/Scheduler.vue` 和导航入口，消费已有受鉴权保护的 `/api/scheduler`。展示面板运行时和账号自动化的任务数、运行状态、间隔、上次/下次执行和错误原因；只读，不会改变自动化策略。
2. **首次改密服务端拦截**：当 `mustChangePassword` 为真时，除会话验证、改密、登出外的 API 一律返回 `PASSWORD_CHANGE_REQUIRED`。
3. **会话生命周期与实时连接保护**：管理令牌支持 12 小时绝对有效期、2 小时无活动失效（可通过环境变量调整）；过期、登出、封禁和删用户均会撤销令牌并断开 Socket。Socket.IO 仅接受同源和本地开发白名单来源。
4. **微信凭据回显收紧**：微信配置读取与保存响应只返回配置状态和密钥提示，不再把原始 API Key 下发给浏览器；后台留空密钥字段会保留既有密钥。
5. **微信服务诊断**：后台新增只读“检查服务”入口；仅以短超时、无凭据 `GET` 判断当前本地/HTTPS 服务是否可达，不申请二维码、不传账号信息，也不自动安装任何协议服务。
6. **错误提示脱敏**：全局 Vue、Promise 和窗口错误不再把原始内部异常直接展示给用户，原始信息仅保留在浏览器控制台。
7. **验证**：`pnpm -C core test` 38/38 通过；`pnpm -C web build` 通过；调度中心已在本地运行页面核验。

## 分阶段开发清单

### 第一阶段：必须马上完成

| 项目 | 改造点 | 影响 |
| --- | --- | --- |
| 会话生命周期 | `admin.js` + `user-store.js`：绝对/空闲 TTL、改密/禁用即撤销、Socket 同步失效 | 降低令牌泄露风险；用户需重新登录。 |
| 微信接入健康度 | 新增本地协议服务 health/版本 API、后台配置向导、禁用态和可信服务说明 | 解决“入口存在但无法登录”的误导；真实接入仍需用户认可协议服务风险。 |
| 操作审计和失败诊断 | 新增审计服务/数据文件、管理改动记录、最近安全日志导出 | 可追溯性和故障定位显著提升。 |
| 前端关键 E2E | 覆盖添加账户、改密、设置保存、危险操作确认、调度、移动端菜单 | 降低 UI 回归风险。 |

### 第二阶段：重要功能升级

| 项目 | 改造点 | 影响 |
| --- | --- | --- |
| 执行历史与告警 | scheduler/worker 记录任务耗时、跳过、失败、重试；新增 history API/UI | 长期运行可诊断。 |
| 模板与导入导出 | `store` 增加 schema 版本与脱敏导出；设置页加预览/校验/回滚 | 更易复制策略和备份。 |
| 可访问性与前端拆分 | 模态焦点管理、Select 键盘支持、图片文本、拆分超大页面 | 改善键盘/移动体验和维护性。 |
| 数据层演进 | 单机先引入 SQLite 迁移；多实例才升级 PostgreSQL/事务/锁 | 为未来规模化准备，避免提前分布式化。 |

### 第三阶段：条件启用的长期拓展

| 项目 | 前置条件 | 原因 |
| --- | --- | --- |
| 精细 RBAC、MFA、凭据库 | 多人、公网或商业运营 | 个人本机环境投入回报低。 |
| WebHook、插件 Hook API | 已有稳定审计、权限和限流 | 避免第三方扩展扩大攻击面。 |
| 队列、分布式 Worker、HA | 已验证单机资源瓶颈和多实例需求 | 当前 JSON 数据层不支持直接横向扩容。 |
| AI 助手 | 有脱敏策略、诊断数据和明确模型边界 | AI 不应替代自动化安全规则或凭据管理。 |
