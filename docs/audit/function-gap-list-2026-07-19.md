# 功能差距清单与 2.0 升级范围

- 日期：2026-07-19
- 基线：`v2.3.2`，主线未合并其他 worktree 分支
- 原则：每项必须服务于多账号自动化的日常运营、故障处理、数据安全或可维护性；不为展示而添加功能。

## P0：纳入 2.0 首次发布

| 能力 | 当前已有 | 当前缺少 | 2.0 最小闭环 | 价值与维护成本 |
| --- | --- | --- | --- | --- |
| 任务执行历史 | 调度快照、账号日志 | 重启后不可复盘成功/失败/耗时 | `task_runs` 持久化、账号隔离查询、调度页时间线 | 高价值，中等成本 |
| 失败诊断包 | 普通日志、状态接口 | 失败上下文需人工拼接 | 关联最近日志、任务记录、账号状态、脱敏策略快照的可下载诊断包 | 高价值，中等成本 |
| 管理操作审计 | 登录日志 | 配置/用户/卡密/账号变更无追踪 | actor、动作、目标、结果、脱敏前后摘要、保留策略和后台查询 | 高价值，中等成本 |
| 运行环境 Doctor | `/api/ping`、Docker 健康检查 | 数据目录、配置资源、端口、磁盘和版本问题不可诊断 | 只读 Doctor API 与后台健康页 | 高价值，低成本 |
| CI 质量门 | 本地 test/build/e2e 脚本 | 无 PR/主线持续验证 | 冻结安装、lint check、core test、web build、Playwright smoke | 高价值，低成本 |
| 版本 Manifest | package 版本和 CHANGELOG | 无机器可读构建信息 | `version.json`、构建日期、升级摘要、界面版本入口 | 高价值，低成本 |

## P1：完成 P0 后进入同一升级周期

| 能力 | 当前已有 | 建议升级 | 前置条件 |
| --- | --- | --- | --- |
| 统一失败策略 | 局部 timeout/catch | 任务级 timeout、有限重试、指数退避、失败后告警或停用策略 | P0 任务历史 |
| 日志查询与导出 | 基础筛选、清空日志 | 时间范围、账号/任务过滤、CSV/JSON 导出、关联 ID | P0 审计与 task run schema |
| 配置导入导出 | 手工设置页面 | schema-versioned 脱敏策略包、校验、预览、确认应用、回滚点 | 策略 schema |
| 批量账号运维 | 单账号启停、好友批量操作 | 筛选后批量启动/停止/重启，明确确认与结果汇总 | Worker 管理幂等性确认 |
| 策略 Dry Run | 分析推荐、直接保存 | 保存前显示将收获/种植/购买的计划，不发真实请求 | farm plan/apply 边界 |
| 告警规则 | 下线提醒、推送通道 | 连续失败、离线超时、任务超时、任务堆积规则 | P0 历史与失败策略 |
| UI 工作流重组 | 页面和基础组件齐全 | 控制台首页、账户运维、策略、调度诊断的连续路径；统一 Skeleton/空态/错误态 | P0 API 稳定 |

## P2：条件性路线，不纳入首次 2.0 发布

| 能力 | 触发条件 | 不立即做的原因 |
| --- | --- | --- |
| RBAC 与 MFA | 多管理员或公网开放 | 两种角色足够当前本机运营，提前引入会扩大契约面 |
| 凭据加密与轮换 | 需要保存更多第三方密钥或设备凭据 | 先明确密钥生命周期和恢复策略，不能只加一层不可恢复加密 |
| 事件 Webhook | 已有审计、限流和权限模型 | 外部触发会扩大攻击面 |
| 插件系统/工作流编排 | 固定任务模型稳定且出现第三方扩展需求 | 插件 ABI 过早固化会拖慢核心演进 |
| SQLite/PostgreSQL | 数据量、并发或多实例确实成为瓶颈 | 当前 JSON 数据层对单机更简单可靠，迁移必须有演练与回退 |
| 分布式 Worker | 单机资源已实测不足 | 引入队列、租约和状态一致性成本很高 |

## 2.0 实施顺序

1. **基础与发布**：Version Manifest、`lint:check`、CI、Doctor、统一错误代码和可审计的升级元数据。
2. **运行可观测性**：Task Run、诊断包、操作审计、任务时间线、日志导出。
3. **可靠性策略**：超时、有限重试、退避、连续失败告警和账号安全停机策略。
4. **控制台体验**：以“今天需要处理什么”为中心重组概览；补 Skeleton、空态、错误恢复、移动验收和键盘可达性；拆分过大页面。
5. **配置生产力**：脱敏导入导出、预览确认、批量应用和 Dry Run。

## 非目标

- 不新增 UI 框架、图表框架、状态管理库或数据库依赖，除非实现阶段有具体且量化的缺口。
- 不更改 QQ/微信登录协议、Worker 农场主循环或 `core/data` 真实运行数据。
- 不把现有 REST API 一次性改版；新增接口以兼容方式进入，并补契约测试。
- 不把语义版本从 `2.3.2` 回退为 `2.0.0`。产品升级可称“2.0”，发布号默认建议为 `2.4.0`。
