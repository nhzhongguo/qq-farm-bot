## 三、v2.6.0 升级内容（4 大方向 13 项）

### 方向 A：运营报表与数据洞察（补齐 P1 缺口）

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| A1 | **每日/每周运营报表** | 基于 `stats.js` 日归档 + `task-run-store` 生成账号级报表：收获数、偷菜数、任务数、异常数、收益趋势。格式 JSON（机器可读）+ HTML（浏览器打印/邮件正文），**不引入 PDF 重型依赖**；管理员可按账号/日期区间预览与下载，可选推送到告警渠道 | **P0** |
| A2 | **作物策略对比提示** | Analytics 增加「当前账号收益 vs 历史最优策略」差距提示：基于 stats 归档计算近 7 天同策略收益均值，给出可种植作物建议，仅提示不自动改配置 | P1 |
| A3 | **收益趋势增强** | 统计页增加 90 天月度汇总视图 + 多账号同图对比（沿用自绘 SVG，无新依赖） | P2 |

### 方向 B：国际化与体验

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| B1 | **轻量 i18n 框架** | 自研 dict + `t()`（约 200 行，不引 vue-i18n，延续零重型依赖哲学）：语言切换（zh/en）+ localStorage 记忆 + 跟随系统。先覆盖导航/登录/设置/统计等核心页面，其余渐进补齐；后端文案不入 i18n（保持数据与日志中文） | P1 |
| B2 | **虚拟列表** | Friends 好友列表、AdminPanel 审计/登录日志表格数据量大时切虚拟滚动（`@vueuse/core` 已有，优先自研简单窗口化，避免新依赖） | P2 |
| B3 | **批量操作体验** | 批量运维工具栏支持全选/反选/状态过滤；关键操作二次确认弹窗统一 | P2 |

### 方向 C：工程化与 API

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| C1 | **OpenAPI 文档** | 为管理 API 生成 `swagger.json`（手写维护一份精简 schema 或从路由注释生成），挂到 `/api/docs`（生产可关），供第三方接入参考 | P1 |
| C2 | **CI 发布检查联动** | CI 增加：`pnpm release:check`（版本四源一致）+ `pnpm audit --prod`（生产依赖漏洞门禁）+ `pnpm lint:check` 已存在 | P1 |
| C3 | **未用依赖清理** | 引入 `knip` 检测未用导出/文件/依赖；重点核查 `nprogress`、图标包裁剪、`long`/`protobufjs` 使用面；预期 JS 再降 5–10% | P1 |

### 方向 D：性能、数据层与依赖升级评估

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| D1 | **静态资源缓存策略** | 生产部署文档 + nginx 示例：指纹资源 `Cache-Control: immutable` + brotli 优先 + HTTP/2；Docker 镜像内置 nginx 或沿用 `express.static` 并补缓存头（`.br` 已产出，只差响应头） | P1 |
| D2 | **JSON→SQLite 基准评估** | 先出基准脚本：模拟 10 万条审计/登录/卡密流水，对比 JSON 全量读写 vs `better-sqlite3` 的延迟/内存；结论若值得迁移，**仅迁移高频追加型数据**，保留 JSON 导出兼容。⚠️ 注意 `pkg` 打包原生模块需额外配置，风险单独评估 | P2 |
| D3 | **依赖升级验证分支** | 单开分支逐项验证：Vite 8（rolldown 构建收益）、Express 5（路由/异步错误语义变化，需先建路由清单与迁移用例）、pinia 4；**TS 7 观望**（新架构，等 ≥1 个小版本）。每项通过「130 单测 + 11 E2E + lint + build」才合入 | P2 |
| D4 | **前端构建复查** | 核对全部路由视图已 lazy；`DefaultLayout`（31.7 KB）/`index` 是否可再拆；删除 `web/stats.html` 或移出产物 | P2 |

### 方向 E：安全加固（低成本高收益）

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| E1 | **敏感字段静态加密** | 卡密、推送渠道 token、微信代理密钥在 `*.json` 中改为 at-rest 加密（AES-256-GCM，密钥来自环境变量/挂载文件），审计/诊断包脱敏规则不变 | P1 |
| E2 | **secrets 扫描** | CI 增加 gitleaks 或等效扫描，防止 `.env`/密钥误提交（`.env` 已在 .gitignore，需防回退） | P2 |
| E3 | **限流参数配置化** | 登录/注册/卡密领取限流阈值从硬编码改为环境变量可调，管理后台只读展示 | P2 |

## 五、风险与约束

| 项 | 风险 | 对策 |
|---|---|---|
| 兼容性 | 全部新增向后兼容，不破坏现有 API/数据格式 | JSON 存储格式不变；SQLite 迁移仅评估 |
| 静态加密 | 改动 3 个数据文件读写链路，可能与 `.bak` 自动恢复冲突 | 加密仅作用于敏感字段值；写兼容层，先迁移后回退验证；单测覆盖损坏恢复 |
| 依赖升级 | Express 5 / Vite 8 / pinia 4 为 breaking | 独立验证分支 + 全量测试门禁，不满足即保留现状并记录 |
| i18n 范围蔓延 | 全站翻译工作量大 | 首批只覆盖核心页面，`t()` 未覆盖处回退中文，不阻塞 |
| 报表准确性 | 统计口径需与 stats.js 归档一致 | 报表数据直接复用 stats 归档与 task-run-store，禁止另起口径；单测断言样例数据 |
| pkg 打包 | 原生模块（SQLite）与 pkg 兼容性 | D2 评估阶段单独验证 `pkg .` 打包产物可运行 |
| 隐私 | 报表/推送含账号数据 | 报表导出沿用诊断包脱敏规则，路径不落盘原始绝对路径 |
